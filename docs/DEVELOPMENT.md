# Development notes

How OpenShaker is put together, the decisions behind it, and the traps that cost time. For how the
profiles were fitted, see [CALIBRATION.md](CALIBRATION.md).

## Data flow

1. Each **source** runs on its own thread and publishes `Telemetry` frames. Conventions
   (`telemetry.py`): speed in m/s; accelerations in m/s² in the car's frame (+lat right, +long
   forward, +vert up); slip normalized so 1.0 is about the grip limit, negative = locking; wheel order
   FL, FR, RL, RR.
2. The **engine** renders a 10 ms block at a time. It takes the newest frame from whichever source is
   live, calls `on_frame` on each effect once per new frame, then `render` for audio. One effect that
   raises is skipped, and NaN/inf never reach the output. The mix is scaled by the user's master and
   by `output_scale` (1 for games). Demo mode (`runtime.demo_engine`) is a preview, not a parity
   feature: the script stacks many events into a few seconds, so it plays at `DEMO_OUTPUT_SCALE` (0.4),
   lowered per profile by `demo_output_scale()` - one offline render of the 24 s script with the active
   settings, ~0.25 s - so it peaks at `DEMO_TARGET_DBFS` (-7) at most (BeamNG, at HaptiConnect's loud
   BeamNG level, gets 0.12); its own limiter (`HapticEngine.mix_limiter`, None in games) caps the mix
   at `DEMO_MAX_DBFS` (-6.1), so a strength or Master raised during the Demo cannot push it past.
   test_templates.SafeLevelTests covers every shipped profile. The last stage is `PeakLimiter`,
   HaptiConnect's output limiter as measured from its recordings: ceiling 0.985, a per-block peak
   target, 64 samples of lookahead delay, a 128-sample linear attack clamped per sample, and a
   linear-gain release of 0.853 per second. It never waveshapes: a loud burst turns the whole mix down
   by one gain, which comes back at ~0.85 per second (about 0.6 s from a duck to half gain, 1.2 s from
   full silence).
   Below the ceiling the output is the input, 64 samples (1.3 ms) late. It is in engine.py because the
   calibration tools' render cache hashes that file (`optimize.RENDER_CODE`).
3. **AudioOutput** writes the mono block to the chosen channels of the device and zeroes the others.
   The stream is opened as wide as the endpoint (at most 8 channels): a mono stream on a stereo
   endpoint is up-mixed by WASAPI to both sides, which is not "Left" (HaptiConnect leaves the right
   channel silent). Only a driver that refuses its full width gets the narrow stream.

Effects only ever see the latest frame per block. A source sending faster than 100 Hz must not rely
on per-frame deltas: Trackmania derives acceleration from a windowed velocity difference for exactly
this reason, so a crash between two blocks is not lost.

## Files: bundled vs user data

`paths.py` keeps the two apart.

- **Bundled, read-only** (`paths.RESOURCE_DIR`): the profiles and the icon.
  In OpenShaker.exe that is the PyInstaller bundle (`sys._MEIPASS`); from source it is the project folder.
- **User data** (`paths.user_dir()`): `config.json` and `logs/`, always in `%APPDATA%\OpenShaker`
  (`OPENSHAKER_HOME` overrides it, which the tests use). The installed app never writes next to its exe.
- `paths.migrate_config()` copies an older `config.json` into the settings folder once: from the
  project folder when run from source, or from next to the script an old "ButtKicker Haptics" startup
  entry launched. It never overwrites and leaves the old file in place.
- The developer tools (`calibrate`, `record`, `analyze`, `replay`, ...) run from a source checkout
  and write `sessions/` and `profiles/` there.

## Configuration

- `config.DEFAULTS` is the base. `config.json` holds only what the user owns: audio, sources,
  profiles map, presets, `windows_startup_asked`, `haptics_on` (only while it is false), and
  hand-edited effect parameters. It is created on first run (as `{}`); `save_user()` never writes
  profile data into it.
- One-time migrations run in `load()` behind a mark in config.json: the ACE profile move
  (`ace_profile_split`) and the preset switch cleanup (`preset_switch_cleanup`, 2026-09-20). The old
  window stored every on/off switch ON in every preset, which froze them against later calibrations;
  in the forza, forza_horizon5/6, beamng and ace presets the cleanup drops stored switches equal to the
  profile's and stored ONs where the profile is off, and keeps stored OFFs where it is on (the only
  thing that can only be a choice). Trackmania's preset is not touched. The mark lists the presets
  done (ACE was added later, so an older `true` means the other four and ACE still gets its one
  pass); a preset whose profile will not load stays off the list and is tried again next launch.
- The `audio`, `sources`, `profiles` and `game_processes` blocks (`config.USER_BLOCKS`) are saved
  only where they differ from DEFAULTS, and effect parameters likewise. A copied default would
  freeze it: a release that changes a port or a rate would never reach that user. Earlier versions
  did copy them, so `load()` strips values equal to the current DEFAULTS (`_drop_defaults()`) and
  flags `_resave`; the window then writes the slimmer file back once.
- **No profile chosen yet** (a fresh `config.json`, or Demo before any game) means
  `config.FALLBACK_PROFILE` (Forza Motorsport), never the synthetic DEFAULTS, which run close to full
  scale. `config.load(None)` - used by the tools and tests - still gives the bare DEFAULTS.
- A **profile** (`profiles/<name>/profile.json`) overrides effect parameters, including absolute
  gains. `apply_profile()` first resets effects to `base_effects()`, because a profile only overrides
  the keys it defines and stacking profiles used to leak the previous one's gains.
- A **preset** is per game (`presets.<game>.effects.<effect>.{trim, enabled}`). An `enabled` is stored
  only when it differs from the profile's own switch (`set_preset_effect(..., profile_enabled=)`), so a
  recalibration that turns an effect on or off still reaches the user. The effective gain is
  profile gain x trim, so the calibration can never be overwritten from the UI. Two games can share a
  profile (Forza Horizon 5 and 6) and still have separate presets.
- A preset's `enabled` wins over the profile's; a profile's gains do not. When rescaling a profile,
  give every effect an explicit `gain`: one that inherits the default is silently skipped by a pass
  over existing keys.
- **Migrations on load:** `_migrate_games()` splits an old single Forza Horizon entry;
  `_migrate_profile_names()` rewrites paths and preset keys that still use the pre-1.0 folder names
  (`config.RENAMED_PROFILES`); `_migrate_ace_profile()` moves an ACE entry that still points at the
  Forza Motorsport profile (ACE's own `profiles/ace` since 2026-09-18) - presets are per game, so the
  ACE strengths come along. Profile paths stay relative (`profiles/...`); `resolve_profile()` looks
  next to `config.json` first and then in the bundle, and `relative_profile()` saves them relative to
  either. Paths written into shared files go through `config.portable_path()`.

## Sources

**Forza** (`sources/forza.py`). Data Out packets: 232 bytes (Sled), 324 (Horizon 4/5/6), 331
(Motorsport Car Dash). The dash tail starts at 244 in the Horizon layout and 232 in Motorsport. Gear
byte 0 = reverse, 11 = neutral. SurfaceRumble is a per-wheel surface-material code, not a 0-1
roughness: Forza Motorsport sends 0-2.6 (its kerb codes 0.24, 1.5 and 2.6 come with WheelOnRumbleStrip),
Horizon sends 0, 0.12, 0.24 and 0.6 and never sets the rumble-strip flag. FH5 and
FH6 are identical on the wire, so `Runtime._horizon_key()` asks `procs.is_running()` - a toolhelp
snapshot through ctypes, because starting `tasklist` would flash a console in the windowless app.

**Assetto Corsa EVO** (`sources/ace.py`). Named file mappings `Local\acevo_pmf_physics` (800 bytes,
pack 4, ~335 Hz) and `..._graphics` (status 2 = live), falling back to the AC/ACC names whose first
416 bytes share the layout. Gear = raw - 1. The slip ratio is a true ratio (about 0.05 while
gripping), so it is re-zeroed before normalizing. Reads are capped to the mapping's region size.
Each frame keeps the whole physics page in `tele.raw` (the drive log's `raw_hex`), so a logged drive
replays byte-exact. The live app polls at `sources.ace.poll_hz` (200); while something listens (a
`--log` drive) it polls at `LOG_POLL_HZ` (1000), because ACE writes about 316 pages a second.

**BeamNG.drive** (`sources/beamng.py`). Two built-in protocols, merged, no mod:

- *OutGauge*, stock LFS layout, 96 bytes: gear at 10 (0 = reverse), speed at 12 (BeamNG puts wheel
  speed there, negative in reverse), rpm 16, dashLights 40, showLights 44, **throttle/brake/clutch
  48/52/56**. An earlier version read the pedals 8 bytes late, which showed the clutch as throttle and
  the brake as always zero.
- *Motion Sim*, 88 bytes starting "BNG1": position, world velocity, acceleration without gravity,
  up vector, rotation, rates and angular accelerations, at up to 200 Hz. Its default port is also
  4444, so one socket usually gets both.
- Each packet updates its half; a half that goes quiet is dropped (OutGauge after 0.5 s, Motion Sim
  after 0.25 s). Ground speed = |velocity|; slip = (wheel - ground) / max(ground, 2) / 0.15.
- The 136-byte layout of HaptiConnect's own BeamNG mod is still parsed, only for the calibration
  tools that replay it to HaptiConnect.
- `AXES` was checked with `python -m openshaker.beamng_check <logged drive>` on the one recorded drive
  with Motion Sim: the longitudinal axis and its sign are verified (+y follows the ground speed's rate
  of change), the lateral axis (x) is identified only weakly (the effects use its magnitude, so its
  sign changes nothing), and the vertical axis is unchecked beyond plausible magnitudes. Whether the
  impact/acceleration/bump thresholds fitted to HaptiConnect's plugin suit Motion Sim's smoothed values
  is not checked yet.

**Trackmania** (`sources/trackmania.py`). Openplanet's Data Sender plugin: TCP 127.0.0.1:28765,
newline-delimited JSON. Subscribe with `{"type":"subscribe","sources":["vehicle_state"]}`; the
plugin's own rate cap (`tcp.set_max_telemetry_messages_per_second`) is left alone. Each wheel appears twice (flat `FL.slip/damper`
and nested `vehicleState.wheels.frontLeft.slipCoef/damperLen`); both are read. `SlipCoef` is 0 while
gripping and positive once sliding, so it marks the slide, not the approach - the grip warning comes
from sideways load and body slip instead. Surface ids follow `enum class EPlugSurfaceMaterialId` in
Openplanet's `Openplanet.h`; beware the similar `CAudioSourceSurface::ESurfId` and
`EGameplaySpecialType` enums in the same header. Wheel spin and lock come from a rolling radius the
source learns while the car runs straight without slip.

On connect the source switches off the plugin's per-update service-status messages for its own
connection (they share the per-client budget with the snapshots). From the plugin's first status
message it starts a stopped service and lifts the shipped 100 ms broadcast interval to 0; nothing else
is changed. SlipCoef is all but on/off, so a slide's strength is SlipCoef x sideways speed. Suspension
travel runs 25 ms behind with look-ahead, is held while a wheel is in the air, settles after real
landings, and otherwise only passes compression beyond the pre-flight length (Trackmania dampers
stretch fully in the air). Respawns and restarts (`vehicleState.dynamics.discontinuityCount`, or a
position jump) make frames inactive for 60 ms. For 150 ms after a landing, the world-vertical speed
change is left out of `accel_long`/`accel_lat`. Rev range and damper travel are per car in the
profile's `"cars"` block (`tm_tune` writes them there, never config.json); grip limits are per loose
surface (`tm_grip`).

Every UDP listener binds 127.0.0.1 unless configured otherwise, parsers length-check their input, and
a packet that makes a parser raise is counted (`malformed`) and skipped.

## Effects and profiles

`effects/racing.py` holds the calibrated effects and `effects/trackmania.py` the Trackmania-only ones;
profile parameters are documented in the class docstrings
(`curve`, `vel_curve`, `speed_floor_curve`, `rpm_curve`, `template`, `wavetable_harmonics`,
`strip_amp_curve`, `pitch_jitter`, `pitch_hz_per_rpm`, `binary`, `fixed_amp`, ...). `grip_margin`, `surface`, `landing` and
`boost` are off in `DEFAULTS` and on only in the Trackmania profile, so the HaptiConnect-matched games
do not gain effects HaptiConnect never had.

A gear shift fires only between two active frames: after a pause, rewind, menu or respawn (inactive
frames), a gap of over `rebase_gap_s` (0.5 s) or any spell with the effect off (the engine's previous
frame is not the last one the effect saw), the next active frame only records its gear -
HaptiConnect plays nothing there. `gear_shift.fire_into_neutral: false` plays no shot going into
neutral, only on the engagement (HaptiConnect's ACE plugin; its Forza plugin fires on both). `road.strip_per_wheel` (opt-in) gives each
wheel on a kerb its own voice, starting at phase 0 as it reaches the strip, as HaptiConnect sums them.

**Parity keys (2026-09-20).** Opt-in keys for the gaps listed under
[Known gaps in CALIBRATION.md](CALIBRATION.md#known-gaps); without them every effect renders
bit for bit as before (checked against the previous `SuspensionEffect` on every shipped profile).
- `suspension` road bed: `vel_curve_m` (follow `SuspensionTravelMeters`, Forza offset 196, in m/s;
  games without metres use normalized x `metres_per_unit`, 0.15), `vel_span_s`, `vel_time_source:
  "packet"` (Forza's TimestampMS; a repeated packet is skipped), `vel_poll_hz` (sample and difference
  at ~12 Hz, as HaptiConnect polls), `wheel_combine`, `vel_hold_floor_s`, `bed_env: "frame"`,
  `bed_update_hz`, experimental `amp_mpu_ref`/`amp_mpu_exp` (scale by the car's learned metres per
  normalized unit); SurfaceRumble: `surface_gain_curve` / `surface_add_curve`,
  `surface_mode`, `surface_reduce`, `surface_hold_s`; broadband: `bed_noise` (a `BandNoise` voice,
  `band` or `bands` with relative dB, `order`, level `curve`/`floor` driven by the line's amplitude,
  its held velocity or speed); `render_part` renders the line, the noise, the bed or the shots alone
  for measuring. The class docstring has the details. `Telemetry.susp_travel_m` and `packet_ms` carry
  the new inputs; `sources.forza.parse_packet()` decodes a drive log's `raw_hex` into them.
- `acceleration`: `combine` (`max` default, `sum` as HaptiConnect, `power` with `combine_p`),
  `combine_cross` (+k x long x lat), `combine_brake` (the mode while braking) and `max_level` (the cap
  after combining, default 1).
- `impact`: `triggers` (extra OR'd rules on long_lat, vert, accel_3d, susp_vel_m, susp_vel or
  kerb_onset, in jump / excursion / level mode, sharing the cooldown; `last_rule` and `fire_log` name
  the rule behind each hit so false fires can be counted), `jump_window_s` (frame-rate independent
  jumps), `eval_hz` (look only ~12 times a second, seeded phase: short spikes are hit or miss, as in
  HaptiConnect), `fire_delay_s`. Templates: `bandlimit_hz: 0` makes a hard +-1 square (HaptiConnect's
  hit plateau is 0.999; the band-limited one 0.85) and `duty` its uneven halves. The Demo's collision
  spike (demo.IMPACT_SPIKE_S / IMPACT_SPIKE) now outlasts every profile's `min_hold_s`, so the Demo
  plays the hit (tests/test_templates.py checks every shipped profile).
- `engine`: the BeamNG rev-limiter voice (`rev_voice_amp` > 0 turns it on): on at `rev_voice_frac`
  0.98 x max_rpm, carrier 0.99 x max_rpm / 120 Hz, sinusoidal AM 10 Hz depth 0.65, optional
  `rev_voice_hold_hz` (11.72) for HaptiConnect's sampled on/off. The engine duck under it is
  `PeakLimiter`'s, as in HaptiConnect - fit the voice through the limiter, on the full mix.
- `shift_indicator`: `min_gear` with `below_min_gear_scale` (default 0, silent below it).

**No recorded audio ships.** One-shot effects (gear shift, collision, suspension bump) play a
`template` generated by `effects/base.synth_template()` from a handful of numbers - waveform shape
(`sine`, `square`, `saw`), base frequency, duration, attack/release fades, optional exponential decay,
extra harmonics and a peak `level` - and the kerb buzz loops a cycle built by `synth_cycle()` from
five harmonic weights (`wavetable_harmonics`). The numbers were measured on HaptiConnect's output; the
recordings themselves stay out of the repository. `sample` (a WAV) and `wavetable` (an .npy cycle) still
load for profiles the analysis tools learn locally. A template or cycle that fails to build falls back
to the effect's synthesized thump or buzz.

## Audio

- Only shared host APIs are used, ranked WASAPI, DirectSound, MME. **WDM-KS is never picked on its
  own:** it is an exclusive kernel stream, so taking it locks out every other app and every second
  stream of our own. The test tone once failed with `WdmSyncIoCtl: DeviceIoControl GLE = 0x490` for
  exactly this reason. Loopback capture only sees the shared mixer, so a WDM-KS stream is invisible to
  it - a second process measuring "audio reaches the device" proves nothing about the host API.
- PortAudio snapshots the device list when it initialises; an app started at boot can hold a list
  from before a USB shaker enumerated. `refresh_devices()` rescans on every start (never with a stream
  open).
- Device names are matched exactly first, then as a substring, ignoring Windows' "2- " renumbering.
  A missing device raises `DeviceNotFound`; there is no fallback to another output. Only an empty
  name, "(Windows default output)", follows Windows, whose default can become the speakers when the
  shaker is unplugged - hence the README's advice to pick the shaker by name.
- The test tone is mixed into the running stream rather than opening a second one. It is added after
  the master, at 0.8 peak - about as strong as the hardest hits - and after the Demo's own limiter, so
  it plays as strong in Demo as in a game; the output limiter still holds the sum at 0.985.
- A device that stops playing is noticed: `AudioOutput.alive` turns false once PortAudio's
  finished_callback fires, the stream is no longer active, or no audio callback arrived for 2 s
  (`STALL_S`). `App.poll()` then stops the runtime, names the device that stopped, and retries every
  3 s for a minute (`LOST_RETRY_SECONDS`, `LOST_FAST_WINDOW`), then every 15 s, so re-plugging the
  shaker brings the haptics back by themselves.

## Optional outputs

`openshaker/outputs.py` can load an optional extra output package that is not part of this
repository, to drive something beside the shaker. `load_optional_outputs()` imports each name in
`OPTIONAL_PACKAGES` as `openshaker.<name>`, a name built at run time, and calls its `make_output()`
(no arguments), which returns an output object (duck-typed: `start(ctx)`, `stop()`,
`on_preset(preset, profile)`, `status()`, `close()`, and for the window `build_row(parent)`,
`tray_line()`, `stop_now()`, plus optional `label` and `stop_label` strings). A package that cannot be imported - absent, or missing something it
needs - gives nothing and no message; a `make_output()` that raises gives a one-time message. Only the
window passes outputs to `Runtime(..., outputs=...)`, so the console runner, `--log` recordings and
the tests never arm one. The Runtime starts outputs last (once everything else is up) with an
`OutputContext` (sources, cfg, demo, log_dir, preset()), calls `on_preset()` after a profile switch,
adds `status()["outputs"]` and stops them before the sources; every call is guarded, so a failing
output never stops the haptics. The window grids the widget `build_row()` returns under the output
settings; the tray shows `tray_line()` while it returns text, and a "Stop ..." item (`stop_label`,
else "Stop <label>", else "Stop <name>") calls `stop_now()` straight from pystray's thread (both are
thread-safe by contract); quitting calls `close()`. An output keeps its own settings, so config.py
knows nothing of it.

An optional package must never reach the installer: the spec's `PRIVATE` excludes each one, the
computed import name is never followed by PyInstaller anyway (verified by building a scratch copy with
a dummy package, with and without the exclude; a literal import is caught), and build.ps1 fails if one
appears in PYZ/PKG/COLLECT/EXE-00.toc or as a file in the app folder. `tests/test_outputs.py` checks
that every name in `OPTIONAL_PACKAGES` is in both guards.

## Updates

`openshaker/updater.py` (1.0.1) holds the pure parts; `gui.App` schedules and shows them.

- **Check:** `App._schedule_update_check` runs `updater.check()` on a worker thread
  `CHECK_DELAY_S` (30 s) after start, only while `updates.check` is on (Advanced > Check for
  updates; config.json keeps it only when off).
  - It GETs `https://api.github.com/repos/<owner>/<repo>/releases/latest`, derived from `REPO_URL`,
    with urllib: a 15 s timeout per connect and read and 60 s in total, User-Agent
    `OpenShaker/<version>`, no auth, nothing else sent.
  - `release_from()` returns None for drafts, pre-releases, non-`X.Y.Z` tags and anything not newer
    than `__version__`. A newer release must have exactly one `OpenShaker-Setup-X.Y.Z.exe` and one
    `.exe.sha256` asset, each at exactly `REPO_URL/releases/download/<tag>/<name>` (owner and repository
    compared case-insensitively, as GitHub treats them; the tag and the name exactly), with an integer
    size. Otherwise it raises `UpdateError` with the reason. Malformed JSON of any shape is an
    `UpdateError` too.
  - The next check follows the answer: 24 h after a success or an answer from GitHub (a 403 or 429
    included). After a `NetworkError` (no connection, a timeout, a broken transfer) it comes after 10
    min, 1 h and 4 h (`RETRY_AFTER_S`), then daily.
  - Failures are silent in the UI. `App.update_error` keeps the last one, and `updater.log()` appends
    it to `logs/update.log`, which keeps the last 50 lines.
  - `App._offer_update()` shows the answer. "Nothing newer", or a version at or below `updates.skip`,
    hides a bar that is showing, so a pulled release is withdrawn (also when the latest is then a
    skipped one). An `updates.skip` that is not a version is ignored.
- **Show:** no `notify()` and no dialog.
  - `Tray.refresh` swaps in `tray.badged()` copies of the colour and grey icons: a red "!" drawn with
    Pillow shapes, not a font.
  - The menu gets "Update to X.Y.Z" and "What's new" at the top; pystray drops the leading separator
    while they are hidden. While an update runs, the item reads "Updating to X.Y.Z..." (disabled);
    after a failure, "Update to X.Y.Z failed - open OpenShaker" (`App.update_status()`).
  - The window packs `App.update_bar` above everything.
  - Skip this version saves `updates.skip`; only a newer version shows again.
- **Update now** (`App.update_now`):
  1. On a source copy (`updater.is_installed_copy()` needs the frozen exe with `unins000.exe` next to
     it) it opens the release page and stops there.
  2. It sets the busy guard first. If a game is sending telemetry, it shows the window and asks
     (`UPDATE_CONFIRM`).
  3. The worker calls `check()` again. If that is None, another version or a skipped one, it installs
     nothing: `_update_withdrawn` hides the bar and offers what the answer offers, if anything.
     Otherwise it calls `updater.download()`.
     That fetches the `.sha256` and the installer into a new `%TEMP%\OpenShaker-update-*` folder
     within `max(120 s, size / 50 kB/s)`. `_read` uses `read1()`, which returns after one receive, so
     a server trickling bytes cannot hold a 64 KiB `read()` (and the deadline check) open.
     - `url_allowed()` accepts only HTTPS on GitHub's hosts, as the exact authority: no user info and
       no other port. That is checked on every redirect and on the final URL.
  4. The size must equal the API's. The SHA-256 must equal the one on the `.sha256` line that names
     the installer (`<hash>  <name>` or `<hash> *<name>`, UTF-8 with or without a BOM, UTF-16 with a
     BOM, CRLF or LF). A bare hash is refused. Otherwise the folder is deleted (`updater.discard`,
     which only ever deletes an `OpenShaker-update-*` folder in `%TEMP%`) and the bar shows why.
  5. `updater.run_installer()` hashes the file again, then starts it with `Popen([exe, /VERYSILENT,
     /SUPPRESSMSGBOXES, /NORESTART (, /SHOWWINDOW=1)], shell=False)`, detached. It refuses anything
     outside an update folder, and any copy that is not installed.
  6. The app keeps running and holding its mutex, so setup's `InitializeSetup` sees WasRunning, quits
     the app through `--quit`, installs over it (previous folder) and relaunches it.
     - `KeepStartup` and `KeepDesktopIcon` write the Run value and the desktop shortcut on a silent
       update only if they are there already.
     - `SetupMutex` allows one setup at a time.
     - If setup stops after it quit the app (`WasRunning` and not `UpdateInstalled`),
       `DeinitializeSetup` waits up to 30 s for the `OpenShakerRunning` mutex to clear, then starts the
       installed exe again. After a silent run it passes `--update-failed=<ver>` when no file was
       replaced yet, or `--update-incomplete=<ver>` once `ssInstall` had begun (`FilesStarted`): Inno
       keeps no backup of what it overwrote, so the folder may mix two versions. `gui.installer_result()`
       reads either flag (a value that is no X.Y.Z is dropped). `App._installer_came_back` logs it,
       shows it in the bar and sets the tray's "Update to X failed - open OpenShaker". A later check
       replaces the "failed" note with the offer, or hides it; the "incomplete" note, which points to
       the release page, stays until a check offers an update. An interactive install that is
       cancelled after `InitializeSetup` quit the app starts it again the same way, `--hidden` and
       with no flag.
     - If the mutex is still held after 30 s, the app never quit, so setup starts nothing. The app
       watches the setup process (`_watch_installer`): if it ends, or `INSTALLER_WAIT_S` (3 min)
       passes while the app still runs, the bar reports it and Update now works again.
     - An interactive install over an installed copy sets its two ticks in `CurPageChanged
       (wpSelectTasks)` from the current Run value and desktop `.lnk`, not from the previous
       install's tasks (the app's own Start with Windows switch changes the Run value). At
       `ssPostInstall`, an unticked box deletes that entry. A first install ticks both.
  7. Old `OpenShaker-update-*` folders are removed at every start, once more than an hour old, whatever
     the setting. It is local only, and skipped under `OPENSHAKER_OFFLINE`.
- **Release assets:** build.ps1 writes `dist\OpenShaker-Setup-<ver>.exe.sha256` next to the installer
  (ASCII, `<lowercase hash>  <name>`, LF). A release needs both files, or no copy is offered it
  (`update.log` then says which is missing).
- **No network in tests:** `tests/fakes.py` sets `OPENSHAKER_OFFLINE=1`, and the one network function
  (`updater._open`) then refuses. A user can set the same variable. `tests/test_updater.py` covers the
  rest with fakes:
  - versions, addresses and redirects;
  - malformed JSON;
  - `.sha256` encodings;
  - every download mismatch and the deadline;
  - installer arguments and the re-hash;
  - the window side (withdrawn releases, retries, the busy guard, the installer watch, test mode).
- **Dry run against a fake release:** `sessions/_release/fake_release_server.py` (not shipped) serves
  an installer as a GitHub-like release on 127.0.0.1, with the redirect. Set `OPENSHAKER_UPDATE_TEST=1`
  and `OPENSHAKER_UPDATE_API` to its "latest release" URL. Only in this test mode does the updater read
  that variable and accept `http://127.0.0.1` (no other host), and the bar then says
  "[update test mode]". Normal use never does.

## Window, tray and Windows integration

- Tk may only be touched from its own thread. pystray runs its own message loop on a worker thread,
  and the single-instance listener has another, so every callback goes through `App.run_on_ui()`,
  which `App.poll()` drains. Calling Tk directly from those threads fails silently.
- There is no Start/Stop, only the **Haptics on** switch (`App.set_haptics`; the tray's item calls
  `toggle_haptics` through `run_on_ui`). Off stops the runtime - audio stream, game ports, optional
  outputs - clears `_keep_running` so nothing restarts it, and is saved (`haptics_on: false`) so it
  survives a restart. `start()` turns the switch on, so **Restart haptics** is also the way back;
  changes that need a fresh runtime (Games/Demo, the device, Advanced) go through `_restart_if_on()`
  and wait while it is off. `--no-start` is off for one launch and saves nothing. While the switch is
  on, `poll()` retries a failed start every 15 s (`RETRY_SECONDS`), which is how the app recovers when
  the shaker is still asleep at boot. `Runtime.start()` opens the output before it starts any source
  (the engine renders silence until a source publishes): the output is what fails when another
  program holds the shaker exclusively, and stopping a started source waits out its socket timeout -
  up to a second on the Tk thread, at every retry. A start that fails after the sources are up stops
  them again (`_abort_start`); otherwise they would keep the game ports bound after the window
  dropped that runtime, and neither Haptics off nor a restart could free them. pystray reads `checked` only
  when it builds the menu, so the window calls `Tray.update_menu()` whenever a tick changes (this
  switch, and Start with Windows from its box, its tray item or the first-run question).
- The tray's **Send feedback / report a bug** opens `FEEDBACK_URL` (the repository's issue forms)
  with `webbrowser` (os.startfile on Windows, no shell). Nothing is attached or sent - no log, no
  system data; if no browser opens, the message line shows the address.
- A launch that can neither become the single instance nor reach the running one (a hung copy, or
  another program on port 49731) writes the reason to `logs/gui_error.log` and shows it, instead of
  silently doing nothing; so does any exception before the window exists.
- The master slider is saved like every other setting, so a lowered level survives a restart.
- Sliders: `click_to_jump()` makes a click on the track jump there and follow the mouse (ttk on
  Windows only steps toward a click); any mouse button on a slider first closes an open number box.
  Numbers are `ValueBox`es: click to type, Enter / click elsewhere / focus loss applies, Esc cancels.
  Only typing applies (`ValueBox.edited`): opening a number to look changes nothing, retyping the
  shown number does apply it. A double-click keeps the whole number selected. Strengths snap to whole
  percent and Master to 0.01 (it shows as a percentage; arrow keys step 1 %, Ctrl 10 %). Picking a
  preset by hand applies an open number first; when a detected game moves the view to another
  preset, a half-typed strength is dropped (the message says so) and a held strength drag ends
  (`SliderGrip.held`, `end_slider_drags`). Master is not per preset: its number and drag carry on.
- GUI tests: `tests/fakes.tk_root()` makes every Tk root (withdrawn, or off screen, invisible and
  disabled when click positions matter) and hands the foreground straight back - Windows can give a
  new process's first Tk window the foreground. `close_window()` cancels its timers before destroying
  it. Key presses cannot be event_generate'd without the keyboard focus, so tests run the bound
  handler (`test_gui_input.fire`).
- **Start with Windows** is one value named `APP_NAME` under
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: `"<install>\OpenShaker.exe" --hidden` for the
  installed app, `"<venv>\pythonw.exe" "<source>\openshaker\app.pyw" --hidden` from source. The
  installer's checkbox writes it; from source the window asks once. `autostart.migrate_legacy()`
  replaces a value left under an older name ("ButtKicker Haptics") so Windows never starts two copies,
  and the installer deletes that old value too.
- **Start menu:** the installer adds `OpenShaker` to the user's Start menu. A copy run from source
  adds the same entry on start (`autostart.ensure_start_menu_entry()`, in a background thread;
  `python -m openshaker.autostart startmenu` does it by hand): pythonw.exe + `openshaker\app.pyw`
  with the app icon, written through the shell's WScript.Shell object by a windowless PowerShell. An
  entry that already exists - an installed copy's - is never replaced.
- The running app holds the named mutex `OpenShakerRunning`; the installer's `AppMutex` uses it to ask
  the user to quit OpenShaker before an update or uninstall. Before that check (Inno runs
  `InitializeSetup` / `InitializeUninstall` first - verified with a test installer), the installer runs
  the installed `OpenShaker.exe --quit`: the single-instance listener passes "quit" to `App.quit_app`,
  and `--quit` returns once the port and the mutex are free (at most 10 s). `python -m openshaker.gui
  --quit` does the same for a copy run from source, and also stops a console run.
- The console runner (`python -m openshaker`, `--gui` included) takes the same single-instance lock, so
  it refuses to start while the tray app owns the game ports instead of logging an empty drive.
- A venv's `Scripts\pythonw.exe` is a launcher stub that re-runs the *console* `python.exe` recorded
  in `pyvenv.cfg`, so a "windowless" launch still opens a console. `autostart.repair_launcher()`
  copies the base interpreter's `pythonw.exe` over it (skipped in the exe).
- A venv has no Tcl/Tk of its own. `gui.ensure_tcl()` points `TCL_LIBRARY`/`TK_LIBRARY` at the base
  interpreter's copy before the first `Tk()`; PyInstaller sets Tcl/Tk up itself in the exe.

## Building the installer

`installer\build.bat` runs `installer/build.ps1`:

1. Refuses to build without `LICENSE`, or without 64-bit Python 3.13 (`$ReleasePython`: the version
   the pins were made with; numpy 2.5.3 alone needs 3.12+). Running from source needs only 3.10+.
   Cleans `%TEMP%\OpenShaker-build` (or `-BuildDir`) and makes a venv there with `requirements.txt` and PyInstaller at the exact versions in
   `installer/constraints.txt`; a package in that venv without a pin fails the build, so every rebuild
   bundles - and lists in the notices - the same versions.
2. Regenerates `installer/THIRD-PARTY-NOTICES.txt` with `installer/third_party_notices.py` from that venv, so the
   versions and licence texts are the bundled ones: every licence file in each package's `.dist-info`
   (all of `licenses/`, headed by its own path, e.g. numpy's `numpy/fft/pocketfft/LICENSE.md`), Python's
   `LICENSE.txt`, and `installer/cpython-3.13-incorporated-licenses.txt` - the "Licenses and
   Acknowledgements for Incorporated Software" section of CPython's documentation (expat, libmpdec,
   mimalloc, zlib ...), converted from the copy a Python 3.13.0 install keeps in `Doc\html` - plus
   `installer/hacl-star-LICENSE.txt`, the MIT licence of HACL* (hashlib's MD5/SHA code in the Python
   DLL), which those docs do not list: it is the header of each `Modules/_hacl` file in CPython 3.13.0.
   The script refuses to run without either file.
3. Points `TCL_LIBRARY`/`TK_LIBRARY` at the base Python. From inside a venv PyInstaller otherwise
   decides tkinter is broken and silently leaves it out; the build now fails if Tcl/Tk, the profiles or
   the icon are missing from the bundle.
4. Runs PyInstaller on `installer/OpenShaker.spec`:
   - one folder, no console, the icon and the profiles as data;
   - `pystray` collected as plain `.py` files (`module_collection_mode`), because it is LGPL-3.0 and a
     user must be able to replace it;
   - `pystray._win32` as a hidden import;
   - matplotlib, scipy, soundcard and the developer tools excluded. Python's `ssl` (OpenSSL) is
     bundled since 1.0.1, for the update check's HTTPS request (see [Updates](#updates)); its licence
     is in Python's LICENSE.txt, which the notices include, and the build fails without
     `_ssl.pyd`, `libssl-3.dll` and `libcrypto-3.dll`;
   - of sounddevice's PortAudio builds only `libportaudio64bit.dll` kept (the `*-asio` builds contain
     Steinberg's ASIO SDK and load only with `SD_ENABLE_ASIO`).
5. Finds `ISCC.exe` (PATH, the Inno Setup uninstall registry keys, then the per-user and Program Files
   folders) and compiles `installer/OpenShaker.iss` into `dist\OpenShaker-Setup-<version>.exe`, then
   writes its `.sha256` next to it (the release's second asset, see [Updates](#updates)). The
   version comes only from `openshaker/__init__.py`; the .iss refuses to compile without it.

The installer is per-user (`PrivilegesRequired=lowest`, `{autopf}` = `%LOCALAPPDATA%\Programs`) and
has one screen: the Tasks page - Start with Windows and a desktop shortcut, both ticked - whose Next
button installs straight away (no Welcome, folder, group, Ready or Finished page; the button keeps Inno's
"Next" label - a `[Messages] ButtonNext=&Install` override would rename it). It adds a Start-menu shortcut, installs LICENSE (as LICENSE.txt) and
THIRD-PARTY-NOTICES.txt next to the exe - one copy of each - then starts the app and closes. A silent
`/SILENT` or `/VERYSILENT` update puts back the app it stopped (only when the `OpenShakerRunning`
mutex was held before it quit that copy): in the tray (`--hidden`), or with its window when setup ran
with `/SHOWWINDOW=1` (the app's own Update now from the window; `RelaunchAfterSilentUpdate(WithWindow)`
reads `{param:SHOWWINDOW|0}`). It starts nothing otherwise. An update keeps the same AppId, folder and
the previous task choices. `ISCC /O-` compile-checks the script without writing a setup, but still empties
the output folder (`dist\`). The uninstaller removes the
Run value and asks before deleting `%APPDATA%\OpenShaker` (a silent uninstall keeps it). It is not
code-signed, so SmartScreen warns on first run.

## Testing

`python -m unittest discover -s tests`. The tests build synthetic packets for every game, run the
real sources against fake servers and shared memory, render effects offline, and cover config
migrations, presets, the tray menu (with a stand-in for pystray's Win32 icon), autostart (on an
in-memory fake registry), the settings folder, the frozen-app code paths, device selection (a fake
sounddevice), portable paths, malformed input, the generated templates, the output limiter, and the
Demo level with every shipped profile. They never touch the real registry, audio devices, game ports,
running processes or the user's files (`tests/fakes.py`). Only `requirements.txt` is needed. Some tests
open a hidden Tk window. The suite never loads an optional output package (`tests/test_outputs.py`
uses a fake one), so it passes the same with or without one.

Useful checks when changing things:

- `python -m openshaker -v` prints every effect's gain at start and per-effect levels while running.
- `python -m openshaker --demo --no-audio --wav demo.wav --duration 24` renders without a device.
- `--log DIR` records a drive (telemetry with raw packets, plus the app's own output) for the
  analysis tools. Both files are written while the drive runs (`drivelog.DriveLogWriter`, a streaming
  `runtime.WavCapture`), so a killed run keeps what it had; `meta.json` is written at the start with
  `"complete": false` and again at the end. It records the code version, the sources and frames per
  source, the Forza packet kind, the game/preset key, the profile, master gain, every effect's
  enabled/trim, and the ACE suspension scale. A folder that already holds a drive needs `--overwrite`.
  `--stop-file PATH` removes a leftover PATH at start and PATH itself at the end.
- `HapticEngine(..., seed=N)` makes the random draws (gear-shift pitch jitter) repeat, for offline
  renders; the live app never passes a seed.

## Open items

- BeamNG Motion Sim: the axes were checked on one drive only (lateral weakly, vertical not beyond
  plausible magnitudes), and the effect thresholds not yet against Motion Sim's values.
- BeamNG wheel lock, collision and bump levels: no clean HaptiConnect reference yet (its output faulted
  at every such moment); one recording with a clean lock-up and a clean collision would settle them.
- Forza Horizon: laps play 0 to 1.3 dB quieter than HaptiConnect until its acceleration and
  road-rumble sounds are reproduced exactly.
- Trackmania: the loose-surface grip limits are first guesses; drives on dirt, grass, snow and ice
  would fit them (`tm_grip`).
- Assetto Corsa / ACC have not been validated with recordings.
- The collision templates are matched by energy/peak except the two Forza profiles' (HaptiConnect's own
  50 Hz square cycle).
- The parity keys (above): the Forza Motorsport, Forza Horizon and Assetto Corsa EVO profiles use some
  of them; [Known gaps in CALIBRATION.md](CALIBRATION.md#known-gaps) lists what still differs from
  HaptiConnect.
